# Implementation Plan: Q&A Response Ingestion & Storage

**Branch**: `001-qa-response-ingestion` | **Date**: 2026-04-21 | **Spec**: [spec.md](./spec.md)

---

## Summary

Build the foundational data layer for AnswerGuard: ingest historical Q&A pairs from BigQuery into AnswerGuard's own PostgreSQL/SQLite database, and capture new Q&A pairs at runtime via SDK and REST API. The adherence engine and review UI depend on this layer — it must ship first.

**Source connector**: BigQuery (read-only, one-time bulk import, resumable)
**AnswerGuard storage**: PostgreSQL (production), SQLite (local dev/testing)
**SDK**: TypeScript + Python, fire-and-forget capture, <50ms overhead on hot path

---

**Language/Version**: Python 3.11+ (backend API + BigQuery connector), TypeScript 5.x (SDK)
**Primary Dependencies**: FastAPI, SQLAlchemy 2.0 (sync), Alembic, `google-cloud-bigquery`, `pydantic`
**Storage**: PostgreSQL (production), SQLite (local dev) — same schema via SQLAlchemy dialects
**Testing**: pytest (backend), vitest (TypeScript SDK)
**Target Platform**: Linux server (Docker), self-hosted
**Performance Goals**: ≥10K records/min historical import; <50ms p95 runtime SDK overhead
**Constraints**: BigQuery source is read-only; AnswerGuard DB provisioned by client; fail-open SDK
**Scale/Scope**: Medium (1K–50K Q&A responses/day runtime; up to millions historical)
**Project Type**: Web service (REST API) + SDK libraries (Python + TypeScript)

## Key Implementation Notes

### Deduplication
`QAPair.create()` computes `source_hash = sha256(question_text + answer_text + source_system_id)`. Repository uses `INSERT ... ON CONFLICT (source_hash) DO NOTHING` (PostgreSQL) / equivalent (SQLite). Duplicate is counted as `records_skipped`, not an error.

### Resumable Import
`IngestionRun.last_checkpoint` stores the BigQuery `start_index` of the last committed batch. On resume, use case finds the `FAILED` run for the source system, reads `last_checkpoint`, and passes it as `start_index` to `BigQuerySourcePort.read_rows()`. Checkpoint updated after each full batch write.

### Fail-open SDK
Python: `capture()` submits to a `ThreadPoolExecutor` daemon thread — never raises, never blocks caller. TypeScript: `capture()` calls `fetch()` without `await` — fire and forget. Both log failures to stderr/console.error only.

### SQLite vs PostgreSQL
`DatabaseConfig.from_connection_string()` inspects the URL prefix. Alembic uses `render_as_batch=True`. JSON metadata uses `.with_variant(JSONB(), "postgresql")`.

### Field mapping validation
`ImportHistoricalDataUseCase` calls `BigQuerySourcePort.get_schema()` before starting. Mismatched columns raise `FieldMappingValidationError` — import does not start, 400 returned.
